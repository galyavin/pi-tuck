# Benchmark backlog

One ranked list. Each item names the claim it strengthens, its cost, and what it is expected to change. Rules: the current runs (main run, main replay, 32k first batch) stay first; every new measurement gets a short addendum, committed before its first result (like `PREREG-32K.md`); results reach `main` through the CTO and the Docs seat refreshes the README from them. Costs are estimates written on 2026-10-31 and are corrected when an item starts.

**What limits throughput.** The local model server (about five streams before it answers 429), the Docker VM (4 CPUs, shared by every live chain; amd64 images need Rosetta, which is set when the VM starts, so it can be changed only between runs), the ChatGPT-plan quota for the frontier summarizer (capped), and my own attention. Per-token models (DeepSeek flash) do not load the local server; they are the way to add work in parallel with the main run. Spend is reported per item; the 32k suite has a $60 stop-and-ask line, the recall benchmark $25.

**The filter for well-known public benchmarks (from the user):** a benchmark adds credibility only if compaction actually fires in it. Otherwise every arm scores the same and the result says nothing, or reads as "no effect". Section "Public benchmarks" checks each candidate against that.

Ranking is by what an item adds to the headline claims per unit of cost, not by effort. "Starts when" is what must be free first.
